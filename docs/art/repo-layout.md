# Art files: what is committed, what is generated

The art lives in this repository under `art/`. This page lists every art
path, whether it is committed, and the command that rebuilds it.

**The rule:** a file is committed only if it cannot be regenerated from this
repository plus the pinned Blender (`tools/blender/BLENDER_VERSION`, 5.2) and
the pinned MPFB (`tools/blender/MPFB_VERSION`, 2.0.18). Everything the build
can make is gitignored, including everything under `client/public/assets/`.
The same rule for the whole repository (screenshots, renders, `.blend` files,
build outputs) and how it is enforced (the pre-commit hook and CI run
`scripts/check-committed-files.mjs`) are in
[`docs/repo-hygiene.md`](../repo-hygiene.md).

Contributors without Blender do not build `client/public/assets/`: they
download the asset release published for their checkout's asset fingerprint
(a hash of every build input, including the committed `art/` sources below;
see [`tools/blender/README.md`](../../tools/blender/README.md), "Asset
releases"). The rows below are what a Blender build regenerates.

## Third-party sources (`vendor_assets/`)

`vendor_assets/` is gitignored and is never an input of a normal build. It
holds third-party source files that are only needed to *regenerate* the two
committed sets of `.npz` files:

- the CC BY 4.0 body sculpts the two bodies are wrapped onto (sources and
  licences in [`art/CREDITS.md`](../../art/CREDITS.md); download them from
  the links there if you need to rerun `wrap_sculpts.py`);
- the Meshy-generated hair models the hairstyles are derived from (not
  distributed).

Anything new placed there must have a licence that allows redistribution of
derived work under CC BY-SA 4.0 and must be credited in `art/CREDITS.md`.

## Every path

Commands run from the repository root. `$B` is
`blender -b --factory-startup --python`; the character build also needs
`BLENDER_USER_RESOURCES=$PWD/.blender-user` (where
`tools/blender/install_mpfb.sh` installs MPFB; `prepare.mjs` and
`build_art_blends.sh` set it when the folder exists).

| --- | --- | --- | --- |

All the `.blend` files are build outputs: the builders overwrite them on
every run, and the scripts are the source. They are gitignored
(`/art/world/*.blend`, `/art/vfx/*.blend`, `/art/characters/*.blend`,
`*.blend1`) but still written at the same paths, because the checks open
them: `check_characters.py`, `check_hair.py`, `check_hair_see_through.py`,
`check_seating.py`, `build_hair.py`, `render_hair.py` and the garment checks
read `art/characters/<body>.blend`.

To rebuild all of them in one go (after `node client/scripts/prepare.mjs`, so
the castle textures and the characters' manifest exist):

```sh
tools/blender/build_art_blends.sh                 # world, characters, vfx
tools/blender/build_art_blends.sh world vfx       # or some of them
```

### Review renders

Optional stills for reviewing a change; they are gitignored and never
inputs. Each command writes into `art/renders/` (or any `--out`):

| Folder | Command |
| --- | --- |
| `renders/greybox/` | `$B tools/blender/render_previews.py -- --world client/public/assets/world --layout data/world/layout.json --out art/renders/greybox` |
| `renders/dorms/`, `renders/furniture/`, `renders/school/` | `build_dorms.py -- --render --furnish`, `build_furniture.py -- --render`, `build_school.py -- --render [--people]` |
| `renders/icons/` | `$B tools/blender/icons/render_icons.py -- --sheet art/renders/icons` |
| `renders/characters/` | `$B tools/blender/characters/render_characters.py -- --assets client/public/assets --out art/renders/characters`, `render_adoption.py`, `render_hair.py`, `check_hair_see_through.py --out` |
| `renders/vfx/` | `$B tools/blender/vfx/build_vfx.py -- --render art/renders/vfx`, `vfx/render_duel.py` |
| `renders/toon/` | `$B tools/blender/world/render_toon.py -- ...` (options in `tools/blender/README.md`) |
| `renders/npcs/` | `$B tools/blender/npcs/render_npcs.py` |
| `renders/garment-shapes/` | `render_garment_shapes.py` |

The body comparison sheets (`render_body_trial.py`, `render_wrap_trial.py`,
`render_wrap_sheets.py`, `render_head_trial.py`) also need the sculpts in
`vendor_assets/`.

## Pinned tools

| Tool | Pin | Checked by | Install |
| --- | --- | --- | --- |
| Blender | `tools/blender/BLENDER_VERSION` (major.minor, `5.2`) | `client/scripts/prepare.mjs` (before any Blender step), every build entry script (`tools/blender/pins.py` `require_blender()`), the two Blender test runners | https://www.blender.org/download/ (all 5.2.x: https://download.blender.org/release/Blender5.2/) |
| basisu (optional) | `tools/blender/BASISU_VERSION` (major.minor, `2.50`) | `prepare.mjs` warns before the castle textures or portrait backdrops step when it is missing or another version; `tools/assets/publish.sh` refuses. Without it those two steps write PNG only, which the client loads instead | https://github.com/BinomialLLC/basis_universal/releases (or a package manager, e.g. `brew install basis_universal` on macOS); `$BASISU` names the binary |
| MPFB | `tools/blender/MPFB_VERSION` (`version`, `sha256`, `url`: 2.0.18) | `prepare.mjs` (before a character build), `build_characters.py` (`pins.require_mpfb()`), `charlib/mh_source.py` `enable()` | `tools/blender/install_mpfb.sh` (downloads 46 MB from extensions.blender.org) or `tools/blender/install_mpfb.sh --zip <zip>` (offline) |
